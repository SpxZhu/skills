# 决策呈现与执行确认

供 `sgrill-me` 与 `sgrill-with-docs` 共同读取的适配规则。源技能决定何时调查、提问、记录文档以及结束访谈；本文件仅决定如何呈现已形成的决策问题，以及何时允许开始实施。

## 呈现入口

在源技能准备提出当前决策问题时，保留其问题集合、依赖关系、推荐答案与理由，再按下方顺序选择呈现方式。此时简述与这些问题有关的分析和取舍即可；其他分支的调查仍按源技能继续，不为等待所有调查结束而推迟已就绪的问题，也不提前询问依赖尚未解决的问题。

沿用源技能题号，跨轮保持唯一；同一题的选项字母与含义在展示和提交中保持一致。问题措辞保留“是”表示接受该题推荐答案的语义，并允许用户自定义答案。呈现整轮问题，不为适配工具容量拆分源技能的一轮。

## 决策收集：按顺序回退

### 1. 原生选择卡片

仅在当前模式允许使用、能容纳整轮问题、每题支持自由输入且能等待用户提交时使用。按工具约束设置选项及推荐顺序，一次提交整轮问题。

同步工具等待答案返回；异步工具使用宿主支持的等待机制。依赖答案的工作等收到回答后再继续，其他工作由源技能安排。若结束当前回复会关闭卡片，则在提交前保持该回复；宿主无法维持提交入口时，回退下一种方式。

### 2. 内嵌交互决策表

原生卡片不可用时，检查宿主是否支持持久展示，并能把按钮提交的内容发送回当前对话。具备两项能力才使用；有 `visualize` 技能时读取其指令实现。普通 Markdown 表格、静态单选符号或只能本地保存的页面不满足此条件。

表单标题为“第 N 轮决策表”，每题包含题号、问题、带字母的选项、推荐标记与理由、独立自由输入框，末尾提供“提交本轮决策”按钮。允许仅填写自定义答案；选项与补充文字同时存在时一并提交。提交载荷包含轮次、完整问题、所选答案与自定义文字，用户无需手写编码。

展示文件放入宿主允许的展示目录。随本轮回复展示表单并等待真实提交；若无法真实回传，使用题号编码回复。

### 3. 题号编码回复

前两种方式均不可用时，简述限制，列出完整文字决策表：题号、问题、带字母的选项、推荐答案及理由。提示用户可回复 `Q1:A Q2:B`、`Q3:自定义答案` 或“全部按建议”，然后结束回复等待。

## 回答交回源流程

以用户主动提交或明确回复为答案。预选、编辑、保存、工具返回已创建、关闭卡片和等待超时均不算回答；空结果保持待定。收集方式失败时保留已收到的答案，仅回退收集余下问题。

将答案和补充条件交回源技能，继续其原有判断与追问。推荐与用户确认分开记录；“全部按建议”只覆盖当前展示的问题。答案有歧义、冲突或缺项时交由源流程处理，已确认且未变化的答案直接复用。

## 全部决策完成后的执行确认

源技能完成全部决策、满足原有完成条件后，输出一份可核对的最终汇总：

- 目标、交付物、实施范围与明确排除项。
- 已确认的关键决策、约束、依据、风险与验收标准。
- 准备执行的具体动作、影响范围，以及已产生的讨论文档变更（如有）。

若仍有影响正确性或范围的未决问题，交回源流程继续处理。汇总末尾说明本包装技能要求执行前确认，链接本规则，并询问：“请确认以上汇总，并明确是否开始执行。可回复‘确认汇总，开始执行’，或提出修改。”随后结束回复等待。

**实施门禁：** 只有收到用户针对最终汇总的明确确认与开始执行授权，才能在其范围内实施。收到最后一轮决策答案、认可理解、提交决策表、沉默，以及汇总之前的泛化执行意愿，均不能代替这一步。等待期间保持在讨论与记录范围，不修改业务代码或配置，不运行有实施副作用的命令，不发布，也不委派提前实施。

用户修订决策时，交回源技能处理受影响部分，再提交更新后的汇总确认；含糊回复只澄清缺少的执行授权。有效确认后的未变范围直接复用授权，其他适用的专项门禁继续生效。
